# Content credentials in [!UICONTROL Creative Studio]

[!UICONTROL Creative Studio] automatically attaches content credentials to content that's generated or edited with generative AI, so that the provenance of your ad content is recorded as durable, invisible metadata. The credentials follow the standard of the [Coalition for Content Provenance and Authenticity](https://c2pa.org/) (C2PA).

## Actions that attach content credentials

The following table summarizes when Content Credentials are attached, based on the image action performed in the [!UICONTROL Creative Studio] AI Assistant.

| Action | Description | Content credentials attached? | Use case example |
| --- | --- | --- | --- |
| **Generate an image** | Create a new image from a text prompt, from a reference image, or generate a similar image | Always. The image is generated by generative AI, so it always carries a fresh Content Credential. | A banner image for an email campaign is generated from a text prompt describing the desired visual. |
| **Crop an image** | Adjust an image to requested dimensions | Only if the source image already had a Content Credential. Cropping recreates the image's pixels, which would normally erase that Content Credential, so AI Assistant reads it from the source image before cropping, then rebuilds and re-attaches it to the cropped result. Cropping itself does not add a new generative AI action, it preserves the existing one. | A generated banner image is cropped to fit a web page: the Content Credential is preserved through the crop. </br> An uploaded stock photo used as a push notification background is cropped to fit the screen: since the stock photo carries no generative AI action, no Content Credential is created. |
| **Add a text overlay** | Render generated text on top of a background image | Only if the background image already had a Content Credential. Rendering the overlay produces a new image from the background plus the text, which would normally erase that Content Credential, so AI Assistant reads it from the background image beforehand, then rebuilds and re-attaches it to the result. The overlay step does not add a new generative AI action. | A promotional headline is rendered as a text overlay on a generated background image for a landing page: the Content Credential from the background image is preserved. |
| **Overlay images** | Composite two or more images together | If any of the source images have a Content Credential, the combined image carries all of them, merged into a single Content Credential. Compositing produces a new image from the sources, which would normally erase those Content Credentials, so AI Assistant reads each one before compositing, then builds a single combined Content Credential listing every source that contributed a generative AI action. | A generated product image is composited with a generated background for an email header: the result carries a Content Credential reflecting both generative AI sources. <br> Two uploaded brand photos are composited into one collage: since neither source carries a generative AI action, no Content Credential is created. |

## Content types and their scope {#cc-content-types}

* **Images**: Covered. Content Credentials are attached when images are generated with generative AI, and preserved through cropping, text overlay, and image overlay operations performed by AI Assistant.
* **Text**: Not applicable. Text-only outputs of AI Assistant, such as copy generation, translation, and brand alignment suggestions, do not require Content Credentials.

## What happens as your content moves {#cc-content-moves}

Content Credentials travel with the image file. When an image that was generated or edited with generative AI is downloaded or exported from Adobe Journey Optimizer, its Content Credentials are preserved. [Learn more about Content Credentials](https://helpx.adobe.com/firefly/using/content-credentials.html){target="_blank"}.

Some ways of bringing images into your content, such as extracting an image from a PDF or from an embedded (base64) source, may not preserve the original Content Credential. In these cases, no Content Credential can be read from the source, and none is created for the result.






* **Generate an image:** When you use the [[!UICONTROL Ad Variations Generator]](/help/creative/creative-studio/creative-studio-manage-standard-ads.md#generate-ad-variations) to generate new background images for standard ads, a credential is attached to the image.

* **Resize an image:** When you use the AI chat interface to modify existing content for standard ads<!-- I don't think this is possible: or dynamically-generated ads-->. Editing an asset that already carries a credential causes the existing [!DNL Creative Studio] credential to be resigned to include the new action. Examples:

* **Crop an image:**

  * Cropping an image without a Creative Studio content credential adds a credential.

  * Cropping a generated image without applying any non-AI edits (such as text overlays or drawing), so that the updated image is considered fully generated, re-signs the credential to include the original image as a `parentOf` ingredient and a `c2pa.cropped` action.

>[!NOTE]
>
>[!DNL Creative Studio] preserves any existing credentials that are already attached to uploaded files, including credentials created from Adobe GenStudio and Adobe Experience Manager. When an uploaded file is edited using generative AI, [!DNL Creative Studio] attaches a new credential in addition to the existing credential.

## When does the credential include, and when it created?

For each GenAI generation or alteration, the following are included in the credential. If an asset is altered multiple times, then each operation appears in the credential.

* Timestamp (date + time)
* Model name + version (Adobe Firefly / gemini-flash for images<!-- ; Anthropic claude-sonnet-4-5 for text -->)
* Unique identifier (UUID per operation)

The credential is signed with the full provenance chain when a user downloads an asset or it is sent to be served in an ad.
